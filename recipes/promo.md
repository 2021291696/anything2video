# 配方：promo（产品/服务宣传）

**定位一句话**：给一个产品或服务，产出一条以「钩子→卖点→证明→CTA」为骨架的短宣传片——关键词大字 + 品牌色纪律 + 代码绘制动效为主，15–90 秒，用于投放、官网、发布会场合。不做原理讲解（那用 `explainer`），不做实拍剧情片。

## 1. 叙事骨架与 beats

骨架：**钩子（0–3s）→ 卖点 ×2–3 → 证明 → CTA 端板**。

| 拍 | 时长 | 旁白 | 画面任务 |
|---|---|---|---|
| 钩子 | 0–3s（帧 0–90） | 1 句，≤16 字 | 痛点或悬念：一句反问 / 一个反差数字 / 一个「卡住」的状态。首句旁白 0–1.5s 内开口；钩子主标 GlitchIn（白名单第 1 条）。 |
| 卖点 ×2–3 | 每个卖点 6–10s | **每个卖点 ≤2 句** | 一卖点一屏：主标 ≤8 字 + 小注一句 + 一个动效演示（流程 / 对比 / 数据块）。卖点间硬切或甩出。 |
| 证明 | 6–12s | ≤2 句 | 数据（Counter 计数）/ 演示实录画面 / 口碑（引语卡）。至少给一条可核实的数字；没有数据就给演示画面，二者不硬凑。 |
| CTA | ≥2s（≥60 帧） | ≤1 句 | 全屏端板：品牌色底 + CTA 主文（动词开头，≤8 字）+ logo + 联系方式/二维码位。旁白在端板前 0.5s 收完。 |

## 2. 视觉 token
- **配色来源**：品牌资产包（`reference/brand-assets.md`）；无包 → **整包回退到 `template/src/recipes/promo.ts` 的内置 promo palette**（电光青 #21E6C1 主色系；回退对照表见 brand-assets.md §4）。全片彩色 ≤3（primary + accent + 至多一个强调），黑白灰不计。
- **大字层级**：钩子/CTA 主文 96–150px；卖点主标 64–96px（边界消歧：纯主标屏——屏上无演示主体——按构建协议大字 ≥96px 执行；64–96px 档用于带演示主体的主标或辅助行，与 workflow-orchestration §3.1 构建协议的冲突按此拆解）；小注 24–28px；品牌帽字 24–28px；卡内标题 40–48px（缺省 44）；卡内来源行/小字与品牌条字 22–24px；证明数字 72–110px（Orbitron）。细则 `reference/promo-style-guide.md` §排版。
- **常驻覆盖层**：顶部品牌帽（y28–72）、底部品牌条（y687–720，**替代章节进度条**——本配方无进度条、无章节卡）；CTA 端板由覆盖层图元 `src/overlay/promo/CtaEnd` 接管全屏 ≥60 帧（镜头按分镜 import；图元库源码由主脚本维护）。
- **图元**：复用 `template/src/ui.tsx` / `fx.tsx`；证明拍数字一律 `BigNumber`/`Counter`（计数 14–26 帧 + 落定白闪）。
- 动效词汇与预算：`reference/promo-style-guide.md` §转场词汇（词汇表出处 a2e `reference/motion-vocabulary.md`）。
- 运动与光效纪律（完整运动链/错相阶梯/物理效果/主光统一/拍点卡点）：`reference/motion-language.md`，与本配方冲突时本配方优先。

### 2.6 每屏材质底档位（反空心门，2026-10-04 增）

中段「视觉谷底」是 promo 最高频缺陷（2026-10-03 a2v-skill-promo 实锤：核心卖点屏 = 两个空线框面板，文案吹「电影级」，独立视觉评审判「合格的信息片、不合格的电影级宣传片」）。分镜表每屏必须声明**材质底档位**，QC 按档验收：

| 档位 | 构成 | 适用 |
|---|---|---|
| T0 空底 | 纯色/单渐变底 + 文字 | 只允许钩子首屏与 CTA 端板（每片 ≤3 屏） |
| T1 程序纹理 | `DotFieldBg` / `ShaderPost`（grain+暗角）/ `TempGrade` / grain 至少其一 | 常态卖点屏的下限 |
| T2 多层材质 | T1 + 主体质感层（光效/粒子/Canvas 绘制/景深层）≥3 视觉层 | 高光时刻与证明屏必达 |

- 连续两屏 T0 = QC 记中；卖点演示屏给 T0 = QC 记高（「单层面板+文字」即空心判定）。
- 材质词汇借用 `reference/materials.md` 的材质词典选语言（岩面/纸纹/雨夜/织机…），但 **promo 不是 AI 帧例外配方**——材质全部代码绘制，禁 AI 图。

## 3. 时长档

| 档 | 旁白字数（按时长 × 密度现算） | 句数 | 镜头数 | 构建 | 骨架切分 |
|---|---|---|---|---|---|
| 15–30s | 15s：70–75 ／ 30s：135–150 | 4–7 | 5–7 | 单 agent | 钩子 3s / 卖点 ×2 每个 5–8s / 证明 4–6s（可并入末卖点）/ CTA 2–3s |
| **45–60s（默认）** | 45s：205–225 ／ 60s：270–300 | 8–10 | 10–14 | 2 agent（每组 5–7 镜） | 钩子 3s / 卖点 ×2–3 每个 6–8s / 证明 6–12s / CTA 3–5s |
| 90s | 405–450 | 14–18 | 16–22 | 2–3 agent | 钩子 3–3.5s / 卖点 ×3 每个 10–14s / 证明 12–18s（数据、口碑两屏）/ CTA 4–5s |

- 字数按**目标时长 × 4.5–5 字/秒现算**，表内档端点区间由此推得（45s：202.5–225 取整 205–225；60s：270–300；15s：67.5–75 取整 70–75；30s：135–150）；成片时长差 >15% 就加/删句子，不靠改语速凑。

## 4. 字幕策略
- 形态：**关键词大字**，无常驻字幕带。每屏 = 主标（≤8 字）+ 小注（一句，≤20 字），不出现第二套文字层。
- 位置：全屏锚 = 主标中心 (640,330)（钩子、独立卖点屏、CTA）；画面主体占上 2/3 时用共存锚 (640,545)；小注在主标下方（主标字号 ×0.55 + 12）px 处。
- 禁放区：主标与小注不得进入 y<110（品牌帽带）与 y>660（品牌条上方缓冲）；入场轨迹不得穿品牌条 y687–720。
- 超预算删词，不缩字号、不折行（折行按缺陷处理）。
- **双语大字层的角色分工**（借 guizang 排版经验）：中英同屏时英文词负责节奏与排版骨架（大字/宽体/字距），中文负责把事情说清楚（主释义行）；两者不逐字互译。
- **旁白逐句文本不上屏**（与 explainer 字幕带的本质差异）；完整口播文案放交付说明。

## 5. 素材策略
优先级：**代码绘制（默认，一切能画的都画）** > 品牌资产包（logo/slogan/色）> 免版权 B-roll（只在产品实景、人群、办公场景这类代码画不像的画面用）。
- B-roll 规则：只免版权来源（Mixkit 等）；单条 ≤4s；去色或压暗后做背景/空镜，不与主标抢焦点。
- B-roll 放 `public/assets/broll/`，登记 `MANIFEST.md`：**sha256 / 来源 URL / 许可 / 用途**（字段沿用 `template/src/common/Footage.tsx` 头注约定）；播放走 Footage 实拍层。
- 禁止：任何现有视频的帧或片段、有版权风险的截图、AI 生成图冒充实拍或数据截图。

## 6. 音频策略
- 旁白：**默认云端 TTS 装配路线（见 `reference/workflow-orchestration.md` §7）**，edge-tts 为回退——回退跑 `template/scripts/tts_build.py`（默认中文 `zh-CN-YunyangNeural` +8%、英文 kokoro-82m `am_liam`）生成 `audio.wav` + `timeline.ts`，**promo 片 tts_build 前先设环境变量 `LEAD=34 CHAPTER_GAP=10`**（tts_build 的时间轴参数走环境变量、无命令行 flag；默认 40+45 使首句 from=85，此组实测首句 from=45——达标判据 1（首句起点 ≤帧 45）的实测参数，lessons 09-28；云端路线按 §7 装配后同样受判据 1 约束）。语速在打样时确认，文案定稿后不改词。**重跑 tts_build（时间轴参数变化）后，混音前必须删除旧的 `audio_narration.wav`**（lessons 2026-09-28：陈旧旁白备份会让重混音把 v1 时间轴混回去）。
- BGM：必配，**三级来源按序选**：①用户指定曲 ②免版权曲库（Mixkit / Pixabay Music，选无主旋律突变的循环段，登记出处）③**程序化原创编曲** `template/scripts/score_gen.py`——段落按镜头/句边界排、BPM 与调式按主体气质选、乐谱源码随项目交付（借 guizang 手法，实现自有）；合成稿经试听/波形验收后才进混音。**旁白段自动压低**——由主脚本在渲染前按 `reference/workflow-orchestration.md` §6 的 BGM 混音模板命令混入（目标电平：旁白段 duck 到 ×0.25、句间与端板回到 ×0.6），混完 `audio.wav` 即成片配音轨；CTA 端板最后 1.5s BGM 淡出 ≥20 帧，**淡出锚点=成片总秒数−1.5**（不要锚在旁白尾）。
- 音效（可选标准轨，默认不做、启用时按本条全做）：UI 类动作音（点击/弹出/切换/计数完成/whoosh）全片 ≤6 处、不与 GlitchIn 同帧；流程=分镜表声明音效事件表（镜头/动作帧/音效类别）→ `make_sfx.py` 生成原创音效或免许可素材（登记出处）→ `sfx_landmarks.py` 实测每条 onset/peak → `cue.at = 动作帧÷30 − onset`（短音钉 onset、whoosh 钉 peak）→ 事件按时间戳预拼成 `sfx_track.wav` 作为混音第三路输入，**音效出现时音乐让位**（侧链同旁白）。

## 9. 审美锚（开工前定死三件事，写进 `config.ts` 头注）

§2 的配色纪律与 §7 判据 1–6 本质是一张**减法清单**：禁蓝紫渐变、禁 emoji、彩色 ≤3、字号下限。减法只挡低级错，不保证画面成立——清单全守完，产出照样可以是一条技术上无瑕、观感上平庸的片子：换掉文案，这条片子和下一条分不出来。先例在案：某片量化指标全部健康（脊轴曲折度 4.03、轴线 u≈0.51 都在阈值内），抽帧一看却是灰纸上一坨糊色块——**指标健康 ≠ 画面成立**，减法清单挡不住这种事故。所以每片开工、写第一行分镜代码之前，下面三件事必须先定死，并把答案写进 `config.ts` 头部注释（§7 判据 7 逐项核对；答不出或留「待定」的片子不予开工）：

**1. 色彩弧线——开场 / 中段 / 收尾各是什么色温状态，为什么是这个顺序。**

- 全片不允许「一个底色 + 一个强调色铺到底」。§1 骨架天然三段（钩子 → 卖点/证明 → CTA），逐段报色温状态（具体到 palette token），并写一句顺序理由。
- 反例：「黑底 + 电光青 #21E6C1，全片不变」——这是 §2 内置回退 palette 的默认状态，把默认值原样当设计交差，判据 7 记中。
- 正例：冷色开局（服务钩子的「卡住/疏离」）；中段全片只出现一个暖点，且这个暖色**只给全片唯一的主角**（通常是证明拍最要人记住的那个数字）；CTA 回冷收束。顺序理由一句话说清：先推开观众，再给必须看的焦点，最后收住。
- 预算约束不变：暖点占用 §2「至多一个强调」槽位，全片彩色仍 ≤3；弧线也可以不加色，用同一主色的亮度/饱和阶梯加黑白灰配比完成——但「为什么是这个顺序」必须写得出来。

**2. 每屏的「唯一主角」是哪一个（不是「有没有主角」，是「哪一个」）。**

- 钩子 / 卖点 1–3 / 证明 / CTA 逐屏点名：这一屏唯一被强调的元素是什么（最大字号、唯一动效、唯一高亮所在），其余元素全部降级服务它。
- 反例：证明屏 Counter 数字在计数白闪，主标同时也在 GlitchIn——同屏两个高亮各抢焦点，「其余元素全部降级服务它」落空；两处白名单条目各自合法（判据 5 照过），判据 7 照样记中。
- 正例：证明屏只让 Counter 数字动（计数 14–26 帧 + 落定白闪，§2 图元约定），主标与小注静态在场，字号与颜色全部为数字让路——一屏一个焦点，动效词汇表其余项不用。
- 判定：一屏里同时「发光」（GlitchIn / Counter / 白闪 / 任何高亮动效在场）的东西多于 1 个 = 这一屏没有主角。与 §7 判据 5 分工：判据 5 管全片闪烁总数（白名单），本条管单屏——白名单条目同屏出现两个，判据 5 过、判据 7 照样记中。

**3. 本片独有、贯穿全片的一个视觉元素：开头出现、中段变奏、结尾回归。**

- 这是本片的指纹，不来自通用图元库——别的片子拿不走。
- 反例：全片由 `ui.tsx` / `fx.tsx` 通用图元拼装，元素清单换任何产品照用——没有锚，判据 7 记中。
- 正例：一条从头走到尾的横线——钩子屏是数据线（反差数字从线上长出），卖点屏是分界线（主标与动效演示各占一侧），证明屏是计数基线（Counter 数字立在基线上），CTA 端板是地平线（CTA 主文立在线上方）。
