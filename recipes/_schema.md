# 配方契约（recipes/_schema.md）

一句话：`recipes/` 下每个 `<name>.md` 是一种视频类型的**完整生产规范**；`src/config.ts` 的 `recipe: '<name>'` 选择它。新配方照本文档的九个字段写，写到「照着能执行」的粒度——每个决定给数字（帧 / px / 字数 / 秒），不给「酌情」「视情况」。

## 0. 文件与命名规则
- 路径固定 `recipes/<name>.md`；`<name>` 同时是 `config.recipe` 的合法取值（如 `promo` / `explainer`）。**文件名即契约**，SKILL.md 按名索引，改名 = 破坏接线。
- 一个配方一份文件，配方之间不互相 include；共享规范放 `reference/`，配方只引用路径、**不复制正文**（两份正本必漂移）。
- 允许**转引型配方**：第 2–8 字段可整段由一份外部权威文档顶替（如另一个 skill 的规范），但配方必须自带**引用表**（哪个字段引哪份文档的哪节）与**差异声明**（本配方相对被引权威改了什么）；第 1 字段（定位）与第 9 字段（确认点差异）永远由配方自己写。`recipes/explainer.md` 是合规样本。
- 画布、工程结构、构建/QC 协议以 `template/` 与 `reference/` 为基准；配方只写「本配方相对基准改了什么」，没写的继承基准。
- 增删字段先改本文档（唯一字段清单），再同步各配方。

## 1. 必填字段（九个，按此顺序写）

> 转引型配方（§0）可按其引用表顶替第 2–8 字段；九字段顺序与粒度要求对普通配方不变。

| # | 字段 | 必须写到 |
|---|---|---|
| 1 | **定位一句话** | 一句话讲清：给什么内容、产出什么片、长什么样、何时不用（并指给更合适的配方）。配方标题下第一行。 |
| 2 | **叙事骨架与 beats** | 骨架 = 有序段落（如 钩子→卖点→证明→CTA）；每拍给：时长范围（秒+帧）、旁白句数上限、镜头数范围、画面任务（这拍要让观众看到/感到什么）。每档时长都能从骨架+第 4 字段推出来。 |
| 3 | **视觉 token** | 本配方的外观变量：配色来源（品牌包/内置回退，指向 `reference/brand-assets.md`）、大字层级（px）、常驻覆盖层（帽/条/端板等，逐个给画布坐标）、图元增补（模板 ui.tsx/fx.tsx 之外要补什么）。排版细则指向 `reference/` 对应风格文档，配方只给取值。 |
| 4 | **时长档** | 表：档名（**默认档标出**）/ 旁白字数 / 句数 / 镜头数 / 构建方式（单 agent 或分组数）/ 每拍时长切分。字数按成片密度推（基准：中文 4.5–5 字/秒含留白），并写「差 >15% 加/删句，不靠改语速凑」。**无旁白配方（如 epic）**：时长来源改为章表×章长累计或 BGM 总长锚定（二选一写进分镜表全局约束），档位表改列章数/镜头数/构建方式，超额口径=「差 >15% 加/删章，不靠拉伸单章凑」。 |
| 5 | **字幕策略** | 字幕形态（常驻字幕带 / 关键词大字 / 无字幕三选一）；字号与位置落到画布坐标（px）；文本长度预算；禁放区（哪些 y 段不放内容、入场轨迹不得穿过哪里）。 |
| 6 | **素材策略** | 允许的素材类型与优先级（代码绘制为默认）；外来素材（B-roll/图片）必须写：只免版权来源、放入哪个目录、登记 MANIFEST 的字段（sha256 / 来源 URL / 许可 / 用途）。禁止项单独列。 |
| 7 | **音频策略** | 旁白：默认 TTS 引擎与音色、语速、跑哪个脚本；BGM：有无、来源约束、与旁白的压低规则（给电平倍数或帧规则）、收尾淡出帧数；音效：允许与否与用量上限。 |
| 8 | **QC 判据** | 逐条**可判定**的验收规则；每条 = 判据名 + 量化阈值（帧数/句数/秒数/色数/命中数）+ 核对方法（看哪个文件 / 跑哪个扫描 / 抽哪些帧）。QC agent 按它逐条出 pass/fail。 |
| 9 | **确认点差异** | 相对基准确认点（见 §2）的差表：保留 / 改问法 / 合并 / 删除。**删除必须给理由**（重跑成本或风险为何可接受）；改问法给出可直接贴给用户的话术。 |

### 写作硬规则
- 每个数字可执行：时长用秒或帧（画布 30fps，60 帧 = 2s）；字号/坐标用 px（画布 1280×720）；文本预算用字数。
- 引用外部文档给完整路径并落到节（如 `reference/promo-style-guide.md` §转场词汇）。
- 与基准不同的规则必须显式写「本配方改为…」。
- 配方**不写流程步骤**（建项目/派单/渲染的编排是 SKILL.md 的事），只写规范、取值与判据。

## 2. 基准确认点（所有配方差异的参照系）
四个，出处 a2e `C:/Users/20212/.agents/skills/anything2explainer/SKILL.md` §四个确认点：
1. **时长与语言**（写文案之前必须有答案）；
2. **解说词定稿**（配音之前——定稿后帧号硬编码，是最便宜的干预点）；
3. **配音 TTS 偏好**（跑 TTS 之前，没有就用默认音色）；
4. **打样**（大规模开工之前给用户看样片定风格）。
配方的「确认点差异」字段改的就是这四条；本 skill 的 SKILL.md 负责把最终生效的确认点串进流程。

## 3. recipe 与工程的接线
- `template/src/config.ts` 声明 `recipe` 字段；`'explainer'` 是默认值（该配方 = a2e 现有体系，见 `recipes/explainer.md`）。主会话按 `recipe` 取值打开 `recipes/<recipe>.md` 执行。
- 配方视觉 token 里声明、而模板尚无的覆盖层（品牌帽/品牌条/端板等），按配方在 `template/src/overlay/` 实现或按片补进工作项目——**配方是模板改动的依据，不是事后描述**。
- 配方声明的色值落在 `template/src/recipes/<recipe>.ts` 的 palette token 里进入镜头代码（接品牌包 = 按 `reference/brand-assets.md` §3 的解析规则替换主色 token；本 skill **不生成** `src/brand.ts`——品牌化 = 改配方文件的主色 token），镜头不写彩色字面量（`ui.tsx`/`fx.tsx` 的调色板别名是唯一出口）。
