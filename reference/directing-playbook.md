# 导演手册

质量来自观众能理解的状态变化、真实的质感与节奏。技术门禁负责工程正确，导演决策负责画面成立。

## 定方向

在 research/creative-brief.md 写：受众与一个学习目标、看完能做的动作、最重要的事实、贯穿示例、画幅、语气、主角、首尾关系。选参考时记录具体时间段与可借的方法；只有实际查看过的媒体才算参考证据，制作模型和官方归属单独核实。

对陌生风格，用同一段内容做两种有区别的小样，比较信息是否更清楚、主体是否更真实、节奏是否更舒服，再固定图元库。已验证SKU直接复用并做样张回归。测试风格不能只换强调色。

## 把一句话变成镜头

每镜头写六个答案：观众此时的问题、开始状态、触发动作、结束状态、唯一焦点、与下一镜头的承接。purpose说明要理解什么，action说明真的发生什么，result说明变化证明了什么。

例如“缓存能减少重复计算”：同一请求第一次穿过计算器得到结果并存入缓存，第二次走缓存短路；两条路径保留同一请求标识与计时单位。不要仅显示“快、稳、省”三个标题。

软件教程要展示能照做的步骤、文件位置、正确结果和失败时的修复。真实UI可用经授权的截图或录屏；简化示意标明示意，不能画出不存在的功能。命令按语义切段，给足阅读时间。

不要用一排空描边框假装代码或表格内容。应显示有意义的 token、数值、对象或状态变化；确需空槽时明确其含义并演示填入、清空或容量变化。空态图可以成立，缺少内容的占位装饰不能承担教学。

## 选择表现形式

| 信息任务 | 适合的画面 |
|---|---|
| 因果/流程 | 输入对象被处理并形成输出，保留身份与方向 |
| 比较 | 同一变量、同一尺度、同一观察时段，结论由变化得出 |
| 数量/数据 | 标明单位、来源、轴和示意性质，避免无依据计数 |
| 空间/结构 | 从整体到局部，遮挡与层级能说明关系 |
| 历史/谱系 | 清楚的年代定位、跨章联系、行动中的贯穿符号 |
| 操作教学 | 起始条件、实际操作、产物、一次失败与修复 |

抽象信息优先代码；有机材质、真实人物和产品细节优先可信素材或合格生成资产。材质不能遮住解释，也不能用不相干器物给软件教程增加电影感。

## 构图与运动

一屏一个主要注意目标，其他元素提供条件和结果。优先原生画幅、安全区、文字可读性与真实主体比例。光、粒子、纹理、glitch、相机都按镜头目的选，不作为每镜必填装饰。

有力量的动作包含预备、接触和回稳；解释路径使用连续身份与方向。层间错相用于引导注意，同步动作在比较、齐发、同因果事件中可以成立。相机靠近是为了看清局部，不为凑次数。HUD和字幕保持屏幕空间可读。

停留时间从实际样音、阅读和动作完成测得。复杂屏先减信息再延长；不能靠恒定微动假装内容活跃。有意静止、硬切、纯色与留白可以成立，要在分镜记录目的。反同质化只改变能服务主题的维度，不强迫连续五项全部换掉。

## 多点打样

大规模制作前渲开场、最复杂中段、结尾三处真实运动片段，使用真实音色、字幕和目标尺寸。审定：能否读完、能否看懂变化、注意落点是否一致、声音和动作是否自然。首屏好看不能推导整片好看。

## 多轮优化

每轮先找到最弱镜头，再判断根因：事实不清、稿件不能画、状态变化不成立、主体不可信、布局或时序错误、声音问题、工程失败。先修根因，再修装饰。必要时重写稿件、图元库或整章；不要只叠效果掩盖缺陷。

修复以同内容同片段前后对比验证，同时检查相邻边界和全片回归。记录问题、决定、改动文件、重渲媒体哈希与检查范围。阻塞项清零后仍需整片运动和实际听感审查；未具备能力的检查留为not_performed。
