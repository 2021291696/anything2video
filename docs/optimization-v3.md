# anything2video v3 深度优化与验证

2026-10-05。基于用户原有 ZCode 版本和本机新增规则继续优化，交付 Claude Code、ZCode、Codex、MiniMax Code 四份完整专属包。原 generic 与已存在的链接继续保留；发布范围是用户授权的 GitHub 仓库，不代发抖音或 X。

## 质量瓶颈与决定

旧版积累了图元、8个风格和大量返工教训，主要问题是规则互相覆盖、工程事实没有统一来源、单帧与日志容易被误当整片审查。无限增加效果和重试次数不能解决稿件无法画成动作、主体不可信或画幅错误。

本次把稳定性分为四件可检查的事：观众能理解的因果演示；目标画幅下的实际构图与阅读；可复现工程和素材来源；针对当前真实媒体的完整审查。工程工具负责明确的技术门禁，主控仍负责导演、事实、素材许可和审美判断。

- 每镜头先写观众问题、起始状态、触发动作、结束状态、焦点与承接。缓存教程必须看见计算、保存、再次命中；只让“快/稳/省”标题入场不足以教学。
- 软件教程显示前提、操作、文件位置、结果和一次失败修复。精确信息由代码或真实授权录屏承担，生成世界底必须服务镜头。
- 开场、最复杂中段和结尾都先做真实运动小样；一个漂亮开场不能代表整片。最弱镜头从事实、稿件、状态、主体、布局、声音和工程中定位根因。
- 取消跨配方的固定光效/相机/粒子/微动配额、同 seed 必然一致和固定两轮自动降级。静止、无音乐、纯平图解可以成立，必须有阅读或解释目的。
- 用户否决过的空描边占位框已经转成导演判据：用有意义 token、条目、数值或明确空态/容量变化承担信息。

## 当前指令结构

SKILL.md 或专属入口 → production-contract.md + production-workflow.md → 一个配方 → directing-playbook.md → 按需图元/SKU/素材参考。历史 explainer 快照保留上游署名与组件知识，只有选用该风格时读取；它的宿主、路径、画幅和效果配额不覆盖当前契约。

新增 portrait-wiring.md 明确：Composition 规格来自 project.json，竖屏组件不能导入旧横屏 W/H 当坐标；字幕/HUD也要重排。模板仍保留横屏图元，不声称改两行就自动得到优质竖屏。

合并而不是覆盖本机新增偏好：视频根从 A2V_DATA_ROOT 或 ~/.anything2video/workdir 读取，未知不落当前目录；音乐在分镜前试听圈选，已有无音乐决定或选曲授权不重复询问；风格拿不准先放映样片。已备份原本机 generic。

## 工程与验收改造

### 统一项目事实

project.json 保存 slug、width、height、fps、totalFrames、composition、recipe、draft/production。有意无声声明 audio.mode=silent；这个字段不能掩盖正式旁白丢失。

TTS、混音、章表使用项目 slug/fps。config slug 不一致要求明确迁移。TTS 生成时间轴后同步 totalFrames，保留其他 metadata；旧正本必须 --force 才能更新。无 project 的旧工程只在显式 --legacy-config --fps 时迁移。

章表保留 material 等完整元数据；fit-bgm 同时缩放章长和字幕窗，不能只拉长章而留下旧字幕。任何已有 audio.wav 都保护，静音床仅是临时输入。

### 安全且可修复的渲染

所有模式检查 TypeScript、完整分镜、素材文件与 SHA256，Composition 与项目必须一致。中后段 preview 支持1起开始帧。输出默认保护，显式 --overwrite 才替换；同一输出加锁，失败的 staging 不破坏旧媒体。

每次 bundle 独立目录，关闭共享 webpack 缓存，解决前向试做暴露的 pack rename 竞争。成本是可能增加打包时间，没有声称性能无损。

源码快照记录实际项目输入，包含嵌套 src/build 与自定义组件目录。顶层 renders/stills/fin_frames/qc 和真实依赖/缓存是保留输出区，不放导入源码；已注册镜头落排除区会拒绝。普通 build/out/dist 不再因名字被忽略。源码、音频、素材、配置或锁文件变化使旧证据失效。

### 最终门禁

render 的 .delivery.json 记录真实媒体哈希、源码哈希、模式、帧范围和 ffprobe，视觉与音频初始 not_performed。

check-qc.mjs 要求 production 全片、八项真实审查声明与哈希证据、无阻塞项、AI素材三查通过；独立 ffprobe 计帧和 ffmpeg 全片解码。拒绝 draft、preview、旧媒体/源码、缺项、未审素材和伪造规格。

它验证技术与声明完整性，不能证明人真的看过或听过，更不能自动证明电影感。motion/audio 必须记录实际完整播放/听取，无能力时保留待审，不自动填 passed。

### AI素材

生成器要求明确 material，按项目画幅请求，按 take 保存候选，默认保护旧文件；拒绝凭空回退洞穴。MANIFEST.json 记录实际提交提示词、负向约束、完整64位 SHA256、模型、seed/n/a、真实尺寸和披露，三查默认 not_performed。

手工登记必须给完整 provenance。OpenAI 和 MiniMax 离线响应已验证，但没有把 mocked API 测试写成真实图像质量验收。服务可用尺寸未必精确9:16，需要裁切与信息层合成审查；许可仍单独核实。

## 多轮实际验证

1. 运行时、打包与门禁回归，真实渲染开场/中段/结尾、独立包移位后 init/render。
2. Python 章表与生成素材的离线 provider fixtures、真实本地静音床和音频回归。
3. 独立反向审查复现3个缺陷：音频路径逃逸、TTS固定30fps/旧slug、快照漏掉src/build。修复后增加越界junction/文件链接、帧率/时长、额外源码根失效测试。
4. 独立前向试做16秒中文缓存竖屏样片，生成480帧完整媒体与三段样片。发现数字换行、状态时序与 webpack 缓存竞争；修复并再次实渲。
5. 主控另看首帧、中段与结尾，发现结尾分支仍换行越框，要求统一所有状态并再渲。没有把中段修复推导为结尾通过。

当前 Node **38/38**、Python **41/41**，无失败无跳过；模板 TypeScript 通过。Python41项包含16项音频边界、10项原有音频回归、15项章表/素材回归。实际24fps两秒旁白生成48帧，30fps生成60帧；重复混音正本SHA256不变。

修后同工程并发静帧与全片渲染均成功，原先共享webpack缓存的ENOENT警告未再出现。第195、450帧实际重渲后静态可读，缓存值没有越框。16秒竖屏全片与开场/中段/结尾媒体全部重新核对源码和媒体哈希、计帧并完整解码；仍不据此填运动或听感通过。

核心原问题的直接复现实验和补充验证保存在本机验证目录。公开报告只给必要结论和相对源码，不上传私人绝对路径日志。

发布前合并远端同期更新：保留目录/音乐/风格决策和新增返工实录，辅助脚本的Path.write_text改造补齐缺失导入。样片画廊在1440×900与390×844实际加载11段媒体，没有横向溢出，一个预览的播放时间实际推进；黑首帧问题补11张对应MP4第2秒代表帧封面。原生控件可能暂时遮挡历史片段底部文字，不能由画廊验证推导整片审查完成。

## 发布内容与限制

此前已交付约130.4秒1080×1920教学视频、抖音/X/GitHub长文及独立教程仓库；本轮主线是skill生产与四端移植，16秒缓存片是前向回归样片。

抖音保持原生竖屏、实际设备发布预览和当前AI声明入口；标题限定为“替代Opus做视频的流程”，不声称任意模型能力等价、不做账户交易/地域绕行或必过审保证。X按账号实际Articles/线程权限发布。GitHub保留源许可与素材署名，排除密钥、缓存、参考片和私人日志。

未完成的外部验证：四应用各自独立完整制片、当前真实付费TTS/图像生成、完整人类播放听取及手机发布预览。它们在本轮标为 not_performed，而不是全面平台认证。自动测试通过与用户认可的艺术质量是不同证据。

## 使用与升级

从v3 release选择对应完整ZIP，或在仓库运行 install.mjs。已有专属目录默认保护，先备份再显式更新。四包可分别安装，共享 generic 不删除；下一会话核对实际加载入口与版本。

新任务继续使用共享导演/生产合同。只给主题不能保证精品，详细任务书至少包含受众、学习目标、平台、时长范围、来源和已有决策授权。每轮缺陷用具体原因、实际文件与重渲片段追踪，不能只写“已优化”。
